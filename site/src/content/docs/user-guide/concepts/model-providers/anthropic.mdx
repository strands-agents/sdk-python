[Anthropic](https://docs.anthropic.com/en/home) is an AI safety and research company focused on building reliable, interpretable, and steerable AI systems. Included in their offerings is the Claude AI family of models, which are known for their conversational abilities, careful reasoning, and capacity to follow complex instructions. The Strands Agents SDK implements an Anthropic provider, allowing users to run agents against Claude models directly.

## Installation

Anthropic is configured as an optional dependency in Strands Agents. To install, run:

<Tabs>
<Tab label="Python">

```bash
pip install 'strands-agents[anthropic]' strands-agents-tools
```
</Tab>
<Tab label="TypeScript">

```bash
npm install @strands-agents/sdk @anthropic-ai/sdk
```
</Tab>
</Tabs>

## Usage

After installing dependencies, you can import and initialize the Strands Agents' Anthropic provider as follows:

<Tabs>
<Tab label="Python">

```python
from strands import Agent
from strands.models.anthropic import AnthropicModel
from strands_tools import calculator

model = AnthropicModel(
    client_args={
        "api_key": "<KEY>",
    },
    # **model_config
    max_tokens=1028,
    model_id="claude-sonnet-4-6",
    params={
        "temperature": 0.7,
    }
)

agent = Agent(model=model, tools=[calculator])
response = agent("What is 2+2")
print(response)
```

### Structured Output

Anthropic models support structured output through tool use. Pass a schema to the agent, and Strands generates a tool from it that the model calls to return validated, type-safe data.

<Tabs>
<Tab label="Python">

Define a Pydantic model and pass it to [`agent.structured_output()`](@api/python/strands.agent.agent#Agent.structured_output):

```python
from pydantic import BaseModel, Field
from strands import Agent
from strands.models.anthropic import AnthropicModel

class MovieReview(BaseModel):
    """Analyze a movie review."""
    title: str = Field(description="Movie title")
    rating: int = Field(description="Rating from 1-10", ge=1, le=10)
    genre: str = Field(description="Primary genre")
    sentiment: str = Field(description="Overall sentiment: positive, negative, or neutral")
    summary: str = Field(description="Brief summary of the review")

model = AnthropicModel(
    client_args={"api_key": "<KEY>"},
    max_tokens=1028,
    model_id="claude-sonnet-4-6",
)

agent = Agent(model=model)

result = agent.structured_output(
    MovieReview,
    """
    Just watched "The Matrix" - what an incredible sci-fi masterpiece!
    The groundbreaking visual effects and philosophical themes make this
    a must-watch. Keanu Reeves delivers a solid performance. 9/10!
    """
)

print(f"Movie: {result.title}")
print(f"Rating: {result.rating}/10")
print(f"Genre: {result.genre}")
print(f"Sentiment: {result.sentiment}")
```
</Tab>

### Prompt Caching

[Prompt caching](https://docs.claude.com/en/docs/build-with-claude/prompt-caching) lets Claude reuse
an already-processed prefix of your prompt instead of reprocessing it on every call. In a long
session, the system prompt, the tool definitions, and every earlier turn are identical from one
request to the next, so caching them stops you paying full input price for them again.

Caching is off unless you ask for it. Set `cache_config` to add a cache breakpoint to the last user
message, which caches everything before it, and `cache_tools` to cache the tool definitions:

<Tabs>
<Tab label="Python">

```python
from strands import Agent
from strands.models.anthropic import AnthropicModel
from strands.models import CacheConfig, CacheToolsConfig

model = AnthropicModel(
    model_id="claude-sonnet-4-6",
    max_tokens=1028,
    cache_config=CacheConfig(strategy="auto"),
    cache_tools=CacheToolsConfig(ttl="1h"),
)

agent = Agent(model=model)
result = agent("Summarize the attached report.")
print(result.metrics.accumulated_usage)
# {'inputTokens': 12, ..., 'cacheReadInputTokens': 2505}
```
</Tab>
<Tab label="TypeScript">

Cache activity is reported in the usage metrics: `cacheWriteInputTokens` counts tokens written to the
cache and `cacheReadInputTokens` counts tokens served from it.

#### Choosing a strategy

`cache_config` accepts two strategies, and **on this provider they behave identically**:

| Strategy | Meaning |
|----------|---------|
| `"auto"` (default) | Cache the conversation. On providers that serve non-Claude models this also checks that the selected model supports caching. |
| `"anthropic"` | Cache the conversation, skipping that support check. |

The check is what makes them differ elsewhere: [Amazon Bedrock](./amazon-bedrock)
serves models from several vendors, so `"auto"` inspects the model ID and does nothing when the model
cannot cache. The Anthropic API serves only Claude models and prompt caching is supported on all
active ones, so there is nothing to check and nothing to skip. Both values are accepted so the same
`CacheConfig` can move between providers unchanged.

#### Things to know

- **A prompt below the minimum length is not cached, and no error is raised.** The minimum cacheable
  prefix depends on the model (1,024 tokens for Claude Sonnet 4.5, more for some others — see the
  [cache limitations](https://docs.claude.com/en/docs/build-with-claude/prompt-caching#cache-limitations)).
  If both `cacheReadInputTokens` and `cacheWriteInputTokens` stay at zero, the prompt was too short.
- **The breakpoint moves with the conversation instead of accumulating.** While `cache_config` is set
  each request carries exactly one message breakpoint, so a long session does not accumulate one per
  turn. Cache points in earlier messages, and extra points in the newest turn, are removed, and a
  warning reports how many were removed.
- **`cache_config` and a hand-placed cache point compose.** A cache point you place in the last user
  message is kept where you put it, and automatic placement steps aside. That matters when the newest
  turn ends with content rebuilt on every call — retrieved context, a timestamp, injected state —
  because a boundary *after* that content puts it inside the cached prefix, so every request writes a
  new entry and none ever reads one. Since a cache write costs more than an uncached token, that is more
  expensive than not caching at all. Place the cache point ahead of the per-call content to keep the
  durable prefix cacheable. Your point needs something ahead of it that can carry a breakpoint: if only
  a reasoning block, a media block with a location source, or nothing at all precedes it, the point is
  dropped and automatic placement applies instead. A `ttl` on your point is used as written; a point
  without one inherits `cache_config`'s.
- **Without a cache point of your own, the breakpoint goes on the last block of the newest turn that can
  carry one.** Blocks the API rejects a breakpoint on (a reasoning block, for example) and blocks that
  are dropped when the request is built (media with a location source) are skipped, so the breakpoint
  lands on the nearest block before them. If the newest turn has no such block, no message breakpoint is
  emitted — the request is not cached against an older turn, because a prefix that has stopped growing
  would go stale.
- **`cache_tools` on its own can exceed the API's four-breakpoint limit.** `cache_config` keeps the
  total at one message breakpoint, but `cache_tools` adds its own without accounting for cache points
  you placed by hand. Four hand-placed points plus `cache_tools` is five, which the API rejects; a
  warning names the cause before the call is made.
- **`ttl` defaults to 5 minutes; `"1h"` costs more to write.** See
  [pricing](https://docs.claude.com/en/docs/build-with-claude/prompt-caching#pricing).
- **`cache_tools` works on its own.** It does not require `cache_config`, so tool definitions can be
  cached without caching the conversation. Passing a plain string (`"default"`) only switches it on —
  the value is not a TTL. Use `CacheToolsConfig(ttl=...)` / `{ ttl: ... }` to set one.
- **Moving a TypeScript config over from Bedrock needs one addition.** `BedrockModel` in `strands-ts`
  has no `cacheTools` option — its `cacheConfig` covers the tool definitions too. `AnthropicModel`
  follows the Python surface and keeps them separate, so add `cacheTools` alongside `cacheConfig` or
  tool definitions will not be cached.

### Token Counting

Token counting is used by context management strategies to estimate input tokens before each model call.

<Tabs>
<Tab label="Python">

The Anthropic provider can use the native `messages.count_tokens()` API, which provides exact token counts including system prompts, messages, and tool specifications.

You can enable native token counting with:

```python
model = AnthropicModel(
    model_id="claude-sonnet-4-6",
    use_native_token_count=True,
)
```

When disabled (or if the API call fails), falls back to estimation with a character-based heuristic (characters ÷ 4 for text, characters ÷ 2 for JSON).
</Tab>
<Tab label="TypeScript">

The Anthropic provider can use the native `messages.countTokens()` API, which provides exact token counts including system prompts, messages, and tool specifications.

You can enable native token counting with:

```typescript
const model = new AnthropicModel({
  modelId: 'claude-sonnet-4-6',
  useNativeTokenCount: true,
})
```

When disabled (or if the API call fails), falls back to estimation with a character-based heuristic (characters ÷ 4 for text, characters ÷ 2 for JSON).
</Tab>
</Tabs>
